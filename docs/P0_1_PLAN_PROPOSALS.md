# P0.1 — PLAN uchun tasdiqlashga chiqarilgan takliflar

**Holat: taklif.** Ushbu fayl `LEX_SCRAPING_PLAN.md`dagi kelishilgan arxitekturani o'zgartirmaydi. Laravel 13/PHP 8.5, PostgreSQL, 4 biznes jadval, Database Queue, 1 worker, 2 s interval, Modular Monolith + Services, Markdown, Poppler/Tesseract, Hybrid Sync va Strict Completion saqlanadi.

1. **Discovery scope:** `nat/loc/int/tech/court/oliy` root querylarida til cheklovini bermaslik; source-record IDlarni yig'ib, til graph'i orqali canonical guruhlash. `official` — qo'shimcha kunlik/cross-check; `unique` — status/sana filterlari tasdiqlanmagan yordamchi manba. Sud F/H/J va boshqa mavjud subtoifalar registry'si alohida coverage nazoratida bo'lsin. Kichik testlarni global completeness deb belgilamaslik.
2. **Identity:** faqat o'zaro haqiqiy source til havolalari va mos asosiy rekvizitlar. Qabul qiluvchi organ, sana, raqam, hujjat turi solishtiriladi; tarjimada publication fieldi yo'qligi ziddiyat emas. Ikkala tomonda mavjud fieldlar haqiqatan zid bo'lsa yoki graph yopilmasa, candidate review. Bir xil title, `abs(id)`, body hash yoki bir tomonlama havola o'zi merge uchun yetarli emas.
3. **Barqaror ID:** universal `documents.id` asosiy identifikator. Yangi yopiq verified component uchun opaque source IDlar lexical minimumi eksperimental anchor sifatida tanlandi; saqlangan anchor keyin o'zgarmaydi. Boshqa deterministik boshlang'ich tanlov tanlansa ham ichki ID/alias lookup invarianti saqlansin. Til mappingi, aliaslar, availability va proof provenance mavjud `documents.metadata` JSONB'da joylashsin. Bir tilga zid ikki full text bo'lsa review; avtomatik oxirgisini tanlamaslik.
4. **Transaction/lock:** source doirasidagi umumiy lock ichida barcha verified aliaslar bo'yicha mavjud hujjatni tekshirish, keyin document + barcha zarur contentlar transaction. 2 mavjud documentga urilgan component avtomatik merge qilinmasin. `(source_id,external_id)` UNIQUE JSONB ichidagi barcha aliaslarning unikalligini kafolatlamaydi; barcha writerlar ushbu protokolga rioya qilishi kerak. PostgreSQL concurrency/JSONB query testlari P1–P5'da bajarilsin; GIN yoki yangi jadval hozir taklif etilmayapti.
5. **Status/validation:** biznes status faqat active/pending/inactive. Source metadata, umumiy effective date va matndagi butun hujjatga tegishli kuchga kirish jumlalari tekshirilsin. `Y` pending'ni ham qamraydi; `N` pending emas. Noma'lum label, OCRga tayangan noaniq dalil, listing/card yoki date conflict — validation review; eski yaxshi status/content/hash/last_checked_at almashtirilmasin. Review biznes status bo'lmasin; framework failed job va run diagnostikasi orqali saqlansin.
6. **Admission:** numeric superscript Unicode ko'rinishida raqamlashni saqlasin. Nonnumeric matematik superscript review. Murakkab table uchun katak koordinatasi/spanlar saqlanib, header ma'nosi isbotlanmaguncha review. Rasm/chizma, PDF struktura va tasdiqlanmagan OCR jim o'tmasin. Barcha source'da mavjud full-text tillar o'tmaguncha candidate atomik saqlanmasin. Metadata-only tarjima to'liq matn deb olinmasin.
7. **Thresholdlar — tasdiqlash kerak:** OCR mean word confidence <90 yoki confidence<70 ulushi >5% review signali; bundan yuqori bo'lish auto-accept uchun yetarli emas. 30% dan ko'p content qisqarishi review. Bu raqamlar P0.1 pilot mezonlari, optimal global threshold ekanligi isbotlanmagan. OCRning hujjat darajasidagi accuracy qabul mezoni/manually certified istisnolar jarayoni full importdan oldin kelishilsin.
8. **Checkpoint:** durable checkpoint raw Viewstate'ga tayanmasin. Filter/interval, committed IDlar yoki idempotent dispatch proofi va page fingerprints saqlansin. Viewstate/cookie transient. Invalid/expired/cycling page'da shu segment fresh GET'dan qayta o'ynatilsin; dublikatlar skip. Count yoki listing o'zgarsa complete bo'lmasin. To'liq taxonomy/interval registry reconciliation qilinmaguncha full coverage tasdiqlanmasin.

Bu takliflar schema'ga yangi jadval/ustun yoki biznes status qo'shishni talab qilmaydi. Sqlite prototype PostgreSQL lock/JSONB ishlashini isbotlamagan. Alias lookup yoki review bookkeeping keyin yetarli bo'lmasa, o'lchangan sabab va alternativalar yangi tasdiqqa chiqariladi.

**Gate ajratilishi:** P1 uchun CONDITIONAL GO — ushbu xavfsiz kontraktlar bilan implementatsiyani boshlashga texnik asos bor. Full import uchun NO-GO — coverage, PostgreSQL/queue, quality review, OCR mezonlari, 1000 ta integration test va foydalanish doirasi yopilmagan. P1 foydalanuvchining alohida aniq tasdig'ini talab qiladi.
