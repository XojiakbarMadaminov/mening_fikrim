# Mening Fikrim backend — implemented context

Laravel13 / PHP8.5 / PostgreSQL17 on local Ubuntu. Development database is `mening_fikrim_active`; destructive tests only `mening_fikrim_active_test`. Do not reset/truncate development data. Actual tables/constraints/migrations: [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md), generated by `php docs/p6_1/schema.php`.

## Implemented corpus pipeline

Lex.uz adapter -> globally paced and budgeted LexHttpClient -> existing HTML / Poppler PDF / Tesseract extraction -> reciprocal identity/requisite and language evidence -> unchanged content quality validator -> universal DocumentImporter -> PostgreSQL content and durable run-item outcomes. Source adapters do not write the database.

Canonical documents, signed source identifiers/aliases and language content rows are different units. Unique document/language and source/external identifier constraints remain. Legal active/pending/inactive is separate from content verified/needs_review. Usable review text persists with JSONB reasons; empty extraction has no fake content row. Lower-confidence text cannot replace existing verified text; protected candidates remain available. Language available/not_available/unknown is independent: missing or unknown translations are not confirmed extraction failures.

## Read-only reporting

CampaignReportingService executes curated PostgreSQL REPEATABLE READ / READ ONLY snapshots. Artisan and authenticated GET-only API expose actual counts, quality/availability, scope, diagnostics and timestamps. Unknown/unavailable metrics are explicit; current cohort counts are not historical content-update events. Active-time metrics unavailable in PostgreSQL are not invented from elapsed time.

No user model/table or operational login existed. The reporting API reuses Laravel request authentication and Gate with a configured SHA256 digest for a read-only bearer identity. Empty configuration denies access. This is a machine read-only credential, not a human admin/user management system. No secrets, queue payloads, raw exception/SQL or owner tokens are returned. There is no campaign-control API.

CorpusReportingTools is an allowlisted adapter for external AI assistants. A bounded deterministic Uzbek question adapter returns grounded answers and evidence without a model. No supported Ollama/LLM provider is installed, so no new integration was introduced. Scraping and reports work without any LLM. [API contract](p6_1/REPORTING_API.md), [local runbook](p6_1/LOCAL_RUNBOOK.md).
